# 0005. Use UUIDs as primary keys

## Status
Accepted (2026-10-11).

## Context
Every record needs a unique id. Career Copilot is local-first: in the future,
users may export their data from one machine and import it on another,
or merge data from different databases.

## Decision
Use UUID version 4 (`uuid.uuid4()`) as the primary key for all entities.
The id is generated by the application when a record is created.

## Alternatives considered
- **Auto-increment integers** (1, 2, 3...): simple and compact, but every database
  starts from 1, so ids collide when data from different databases is merged.
  They are also predictable (`/skills/1`, `/skills/2`).

## Consequences
- Ids are unique across machines, so export, import and merge are safe.
- Ids are not guessable (a minor benefit; it is not a replacement for real security).
- UUIDs take more space than integers and are harder to read during debugging.
- Random UUIDs make indexes slightly slower at very large scale; negligible for a single user.
